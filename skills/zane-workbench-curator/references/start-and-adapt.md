# 启动与适配

先检查当前宿主可读包、可写指定范围及可运行Python的能力，内部完成，不向用户列缺项清单。先做当前成果，只有位置确有歧义才澄清；已有授权与清楚的工作区可选合理子目录并说明。

| 当前环境 | 做法 |
|---|---|
| 已有工作台／规则／事项工具 | 找到来源导航、当前任务和更新方式，映射判断／动作／反馈状态后复用，不运行初始化、不再建第二套源 |
| 新目录且有Python | 使用本目录脚本 `scripts/workbench.py init --root <新目录> --mode life|work|career`；人生首次只留持续问题时加 `--minimal`。Python 3.9+、无外部依赖 |
| 仅能读写文件 | 参考assets相应模式，按当前需要写最少Markdown来源／成果／唯一状态；不生成伪装受脚本管理的标记 |
| 纯聊天 | 给实际可复制成果，确需接续才给摘要；不声称安装、落盘或永久记忆 |

初始化要求不存在的目录。已有空目录也先适配，保留规则与用户修改，不整份覆盖为模板。life按生活问题生长，work按业务决策与项目生长，career按岗位任务与职业证据生长；不要给新人全公司财务问卷、给店主集团目录或固定全人生九域。

## 共装和已有数据

三包共装可以共用一套共享组件；任务主责按[任务协议](task-protocol.md)选择。已有目录模式不随新包自动迁移；个人与组织资料默认保持原范围，只传必要且获授权的摘要。真实多用户权限与隔离由宿主工具提供，不因目录分开宣称有访问控制。

多人或同步盘范围先看当前写者与宿主规则；同步不是跨机互斥锁。本包事项工具提供单机写入保护；已有系统使用其原并发协议。可逆授权维护直接做，保留改前版本及恢复方式。

## 回读与交回

核对实际成果可打开、当前源可读、链接有效、没有另一套状态。返回保存位置、当前未完成点与影响使用的工具限制；不把安装成功当能力效果。后续出现新反馈更新受影响产物，再改导航，按需提炼模板。缺记录是未知，无基线不说节省时间。
