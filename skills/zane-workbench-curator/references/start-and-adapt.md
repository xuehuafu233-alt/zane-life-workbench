# 从空白到可用

## 先确定宿主能力
用户不需要懂技术。AI 先核实能否读取当前包、写入指定目录、运行 Python。检查在内部完成，不向用户报告缺少哪些背景或字段；只问影响保存位置或当前成果的缺口；没有长期方向不阻断首次使用。

- 有文件及脚本能力：用户指定新目录后，使用本 Skill 的 `scripts/workbench.py init --root <新目录> --mode work|life|career`。人生首次只保存持续问题时追加 `--minimal`，建立规则、导航、资料与事项载体；方向、人格和领域目录在需要时再增加。Python 3.9+，无外部依赖。目录已存在则不运行 init。
- 能写文件但不能运行脚本：根据 assets/starter 与 assets/work、assets/life 或 assets/career 合并生成最小文件。先明确使用 Markdown 事项真源，概览引用它；不生成假装由脚本管理的状态标记。可只创建当前必要文件。
- 纯聊天：按 assets 中模板给出必要的可复制文本。先完成当前成果，再给接续卡；用户自行保存，下次粘贴必要摘要。不声称已安装、已写盘或永久记忆。

init 用新目录避免覆盖。用户选择现有空目录或已有工作台时，先看入口与相关一两层，复用现有结构；保留原规则，补缺失导航，不建立第二套事项源。只读审计和已明确授权的可逆修复不重复请批；移动或替换的范围不明确时才澄清。

## 调用契约
总控传给辅助 Skill：本轮问题、work/life/career 模式、已知事实及来源、目标输出、根目录、已有真源、授权、尚缺的关键条件。辅助返回：实际完成物、依据、未解决项、需要回填的位置。不重复问已有答案，不让辅助互相调用总控成环；总控负责整合。

第一次成果完成后，只在需要持续行动或等待时建事项。没有必要复用价值就不强制造资产。用接续卡从入口重读，区分同会话重读与另一个会话真实测试。

两套共装到同一工作目录：采用已有唯一事项源和资产索引，工作项目作为人生事项的一个领域；人生总控不能覆盖工作任务已确定的验收标准。两个独立目录之间默认只链接或提供必要摘要，不复制个人数据。

## 迭代触发
找错资料→修导航；输出反复不合格→改验收或流程；旧事实继续支配建议→修依赖判断；重复工作且方法稳定→提取模板或 Skill；维护投入大于实际帮助→删减流程。没有重复使用不自动降级有保存价值的资产。

用户明确授权优化时完成可逆修改、验证与留痕，不机械增加确认环节。长期偏好由用户说明或稳定反馈支持；外部报告中的“全部生态”“主流安装方式”“效果提升”必须有对应证据，不能进入产品承诺。

## 组织战略工作台的最小适配
work 模式用于组织战略版。先保留组织方向、必要来源、当前决策项目、资产与接续卡；用经营问题决定是否增加模型、AI试点或业务单元子目录。不要把作者的集团结构给店主，也不要让高管先整理全公司硬盘。业务工作台不是默认多人权限系统；真实共享/隔离能力由宿主和组织工具提供，未实现不声称具备。

人生版若同时管理企业事项，先确认是否同一资料范围；企业客户数据不因“人生版包含工作能力”就自动复制进个人档案。已有 work 模式目录按现有入口适配，升级 Skill 不自动迁移用户目录。

## 职场风云模式
career 面向个人工作交付与职业成长，使用岗位背景、工作项目、方法与职业证据模板；不要求客户收入、现金模型或经营预算。与 work/life 共用事项脚本，模式只决定新目录模板，不迁移或覆盖已有资料。已有旧工作版目录按当前来源逐项适配，保留用户修改；重命名仅在当前范围清楚时进行。
