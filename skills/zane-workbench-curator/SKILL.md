# 工作台搭建与维护

由总控传入 work（组织经营）、life（人生）或 career（职场）模式。人生从空白保存首个持续问题时优先使用轻量启动；能力检查留在内部，面向用户只交付当前成果、必要问题与接续方式，不罗列未知和缺项。首先读 [启动与适配](references/start-and-adapt.md)，检查用户指定范围的现有入口，按实际能力创建最小结构。用户不需要先懂目录、JSON 或 Skill。

## 创建与使用

脚本路径 `scripts/workbench.py`；首次建台用 init 的 `--mode work`、`--mode life` 或 `--mode career`。共用脚本维护唯一状态，各模式使用自己的模板。运行前确定目标目录并查看是否存在；已有目录走适配。手工与纯聊天模式见启动细则。

工作台中的持续事项采用 [事项工具](references/event-tool.md)，保留证据、版本及更正。只初始化目录不算任务完成；把根目录、真源位置、可用工具和未完成项返回总控继续当前任务。

## 导航与收录

按任务读根级及必要子目录，排除缓存、备份、回收站和凭据。核对正文和来源后判断当前版本，原件与摘要分开；证据不足保留冲突。新材料改变来源、目录职责或常用入口时更新导航，日常附件放局部索引。原件默认保留。

## 健康检查

检查失效路径、多个当前版本、悬空入口和待整理材料。没有资产使用记录只代表未知，不能自动判它无价值或删除。按真实查找、采用和纠错反馈改结构，不预建所有生命域。

当前授权内可逆维护直接做，说明变化与验证；有覆盖或批量移动时保留备份和可回滚映射，范围不清才问。没有明确授权，不扫描磁盘或账户、不上传原件、不执行外部动作。
