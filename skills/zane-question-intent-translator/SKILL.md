# Zane Question Intent Translator

这个 Skill 不是润色提示词，而是帮助用户把“我现在说不清”变成“AI 知道要推进什么、交付什么”。

## 核心动作

```text
用户原话
→ 当前可观察的现象
→ 真正想推进的进展
→ 这轮要作出的决定
→ 会改变答案的关键信息
→ 可直接使用的问题
```

## 工作方式

### 1. 保留用户原意

沿用用户自己的语言、情绪和立场，不为了显得深刻添加隐藏动机。强烈立场可以保留，并明确它是用户当前判断，而不是既定事实。

### 2. 找到进展

判断用户此刻更想：

- 理解一个现象；
- 做一个选择；
- 检查已有判断；
- 设计下一动作；
- 生成一个具体交付物；
- 把经验变成方法。

存在两个真正不同的意图时最多拆成两个版本，不把五六个问题塞进一个超级提示词。

### 3. 锁定当前决定

明确这轮回答结束后，用户应该能决定或完成什么。区分当前决定、紧接着的下一步和更远目标，防止 AI 把终局要求提前压到当前环节。

### 4. 定位当前动作的链路位置

当本轮要设计、执行或评估一个动作，且能识别出相邻环节时，在生成问题前补出三项关系：

- 当前动作服务哪条链：它在什么连续任务或事件链中发挥作用；
- 前一步提供什么：本轮可以直接继承的材料、状态或现实反馈；
- 下一步依赖什么：本轮产出要交给谁、形成什么条件或等待什么反馈。

只追踪当前动作的前后相邻环节，不把整条长期链路一次展开，也不把链路说明写成额外的审计清单。若请求只是解释、一次性回答或生成小交付物，或没有可识别的相邻环节，跳过这一步；不得为了填字段编造链路、补写前一步或追问不影响当前动作的信息。

### 5. 只补会改变答案的信息

检查对象、场景、受众、时间、事实、权限和交付格式。缺口不改变当前动作时，采用合理假设直接继续；缺口会导致完全不同的结果或越权时，才问一个简短问题。

### 6. 生成可直接使用的问题

好的问题通常让 AI 知道：

- 要处理的对象；
- 想推进的进展；
- 当前要作出的决定或交付；
- 已知事实与用户判断；
- （适用时）当前动作服务的链、前一步输入与下一步依赖；
- 需要尊重的真实约束；
- 什么样的答案才算有用。

不必强制写成模板。用户原话已经足够清楚时，只做最小补全；用户只是想获得答案时，完成短转译后继续回答，不把“问题优化”变成新的中断。

## 输出形态

根据请求选择最短可用形态：

- **只要提示词**：直接给可复制问题；
- **想知道自己到底在问什么**：给“真实进展 + 当前决定 + 可复制问题”；
- **多个意图混在一起**：拆成最多两个问题，并说明先后顺序；
- **想直接解决**：用一句话校准意图后继续完成任务。

## 质量标准

- 用户读完会觉得“这确实是我想问的”；
- AI 能据此产出可用结果，而不是继续索要一长串背景；
- 保留用户文风，不改成审计报告；
- 没有引入用户未提及且执行不需要的工具、角色或系统；
- 问题指向当前动作，而不是一次性解决全部未来。

## 边界

- 不制造事实、情绪或动机；
- 不把问题写清误认为已经得到正确答案；
- 不用无限追问延迟行动；
- 不自动替用户发布、发送、付费或作出外部承诺；
- 若请求本身涉及隐私／安全、法律合规、不可逆损失或虚假事实导致实质误导，在完成问题转译的同时指出具体信号和可继续路径。
