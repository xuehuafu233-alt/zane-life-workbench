# 按需生长与减法

工作台增长应来自使用者的真实问题和反馈。目录、资料和Skill是载体，不是完成目标。

| 发生什么 | 优先改变什么 |
|---|---|
| 下次找不到材料或读错版本 | 修导航与来源，不重写整套目录 |
| 新事实出现后仍沿用旧解释 | 修当前判断及直接依赖，不再添加一条相同口号 |
| 一件事需要跨会话行动或等待 | 建一个事项，保留现实反馈触发，不默认设定监控 |
| 用户明确需要反复使用、或同类流程稳定出现 | 先做短模板/检查表；只有独立触发与可检验步骤清楚时才做Skill |
| 第一次遇到重大问题 | 按需调用成熟方法或合适专业支持，不等待重复次数 |
| 输出可用但纠错/维护很累 | 同时承认局部价值与负担，比较简化、换工具、缩范围或停止 |
| 规则越来越多、彼此冲突 | 找实际生效真源，合并/下沉并保留可恢复版本 |

新模块至少说明当前解决什么、依赖什么输入、交付什么、适用边界和如何验证；普通用户无需读这套内部说明。获得改进授权后完成范围内可逆适配，改既有内容保留恢复方法；不让用户学习如何编排多个Skill。无工具能力时直接交付可用模板文本，不声称已安装。

用户请求复盘或现实反馈到来时，问本次是否真的帮助选择、行动、减少反复、复用成果或保有生活；只取会改变决定的信息，不要求全人生打分。没有使用记录代表尚无法判断，不能自动删除长期有保留价值的资料。

有可比较的实际投入才报节省时长；机器等待不等于本人劳动。无基线仍可描述局部帮助、采用与困扰，但不虚构效果率。结束一次事项后保留目标是否解决，后续选择从现实证据继续，不自动派出新任务。
